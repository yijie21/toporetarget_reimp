0 The one-sentence idea

When you copy a human hand demo onto a robot hand, don't just match finger angles — match the geometric relationship between the fingers and the object. That relationship (who touches what, from which direction, at what distance) is the thing that actually makes the manipulation work.

Why we need this at all:

Robots learn dexterous skills (spinning a pen, reorienting a cube) much faster if you give them a reference motion to imitate. Humans are a great source of reference motions — we just record someone doing the task with a motion-capture glove. But a human hand and a robot hand have different shapes, sizes, and joints (the "embodiment gap"). Naively copying the motion produces broken references: fingers pass through the object, contacts slip off, grasps become physically impossible. Train on garbage references → get a garbage policy. TopoRetarget fixes the references.

2 The setup & notation

Before any math, here's what goes in and what comes out. Don't fear the symbols — each is just a labeled box of numbers.

📥 Inputs (the human demo)

$P^h_{1:N}$ — human-hand trajectory: 21 finger keypoints, for each of $N$ frames $q^o_{1:N}$ — object pose (where the pen/cube is) per frame $\mathcal{M}$ — the 3-D mesh (shape) of the object

📤 Outputs (the robot reference)

$q^{base}_{1:N}$ — robot wrist position & orientation per frame $q^{\theta}_{1:N}$ — robot finger joint angles per frame $q^r_t=(q^{base}_t,\,q^{\theta}_t)$ — the full robot pose at frame $t$
Read it like this: the human "showed" the motion (inputs). We must solve for the robot configuration $q^r$ at every frame (outputs) so the robot's hand–object interaction looks and behaves like the human's. The whole paper is one big optimization that finds the best $q^r_t$.

The method runs in four stages. We'll take them one at a time, each with its own animation and equation.

Bone-direction init — a quick first guess so fingers point the right way.
Interaction mesh — build a graph connecting fingers + object into one shape.
Laplacian optimization — the core: preserve local relative geometry.
Constrained solve — add kinematic limits & no-penetration rules, then RL-track it.

3 Stage ① — Bone-direction initialization

First, a rough warm-start: make each robot finger point like the matching human finger.

A "bone" is the segment from one finger keypoint to the next. Its direction $d_k$ is the unit arrow pointing along it. We want the robot's bone directions to match the human's — but cleverly, we match the difference between neighbouring bones (how much the finger bends at each knuckle), which is what survives differences in hand size.

Bone-direction mismatch energy
$$E_{\text{bone}}(q)=\sum_{(k,l)\in\mathcal{A}_B}\big\lVert\,\big(d^r_k(q)-d^r_l(q)\big)-\big(d^s_k-d^s_l\big)\,\big\rVert_2^2$$
In plain English: for every pair of adjacent bones $(k,l)$ along a finger, compare the relative bend of the robot ($d^r_k-d^r_l$) to the relative bend of the source human ($d^s_k-d^s_l$). Square the gap, add them all up. Minimizing this = "bend your knuckles the same way the human did."

$d^s_k$ = source (human) bone direction, in a wrist-centred frame $d^r_k(q)$ = robot bone direction (depends on joints $q$) $\mathcal{A}_B$ = set of adjacent bone pairs along each finger $\lVert\cdot\rVert_2^2$ = squared length = "how far off"

Plus a smoothness term, frame by frame

Per-frame warm start
$$\tilde{q}^r_t:=\arg\min_q\;\lambda_{\text{warm}}\,E_{\text{bone}}(q)\;+\;\lambda_{\text{smooth}}\,\lVert q-\tilde{q}^r_{t-1}\rVert_2^2$$
In plain English: pick the robot pose $\tilde q^r_t$ that (a) matches the human's finger bends and (b) doesn't jump too far from the previous frame $\tilde q^r_{t-1}$ — so the motion stays smooth, not jittery. $\lambda_{\text{warm}}$ and $\lambda_{\text{smooth}}$ just trade off these two wishes.

Why this stage exists: the real optimization (Stage 3) is non-convex. Starting from a sensible, smooth guess keeps it from landing in a weird local solution.

4 Stage ② — Build the interaction mesh

The key trick: treat the hand and the object as one connected shape.

We collect all the points that matter — the 21 hand keypoints and a sprinkle of points sampled on the object's surface — into one big vertex list. Then we connect them with edges (via Delaunay tetrahedralization, a standard way to triangulate points in 3-D). The result is a mesh whose edges literally span the gap between fingers and object. That spanning is what encodes "interaction."

Source (human) vertices
$$V^s_t=[\,P^h_t;\;O_t\,]$$
Stack the 21 human keypoints $P^h_t$ on top of $O_t$, the $N_o$ object-surface samples.
Robot vertices
$$V^r_t(q)=[\,P^r_t(q);\;O_t\,]$$
Same idea, but the hand part $P^r_t(q)$ is the robot's keypoints (they move with joints $q$). The object part $O_t$ is identical.
Two graphs, one shared wiring
$$G^s_t=(V^s_t,\;\mathcal{I}_t)\qquad\qquad G^r_t(q)=(V^r_t(q),\;\mathcal{I}_t)$$
In plain English: compute the edge set $\mathcal{I}_t$ once from the human mesh, then reuse the exact same edges for the robot. So vertex #5 connects to vertex #12 in both graphs. Now the human and robot meshes are directly comparable, vertex-for-vertex and edge-for-edge — that's the whole point. ($N_v = 21 + N_o$ total vertices.)

Watch it assemble: first the hand keypoints and object samples appear, then edges connect them into a single hand-and-object mesh. The cross-edges (faint) are the ones that capture where the hand meets the object.

5 Stage ③ — Laplacian coordinates the heart of the paper

Instead of asking "is each point in the same absolute place?", we ask "is each point in the same place relative to its neighbours?"

What is a Laplacian coordinate?

For a vertex $v_i$, take the weighted average position of its neighbours, then draw the arrow from that average to $v_i$. That arrow — call it $\Delta_i$ — describes the vertex's local shape: how it sticks out from the crowd around it. It's translation-free and captures relative structure.

Optimization moves the robot's vertices until its arrows match the source's arrows — preserving local interaction even though absolute positions differ. Drag the big orange point to feel how $\Delta$ depends on neighbours.

The math behind the arrow

Closer neighbours should matter more, so each edge gets a distance-based weight (an exponential falloff), then we normalize the weights around each vertex so they sum to 1.

Distance-aware edge weights
$$\tilde{w}_{ij,t}=\exp\!\big(-\kappa\,\lVert v^s_{i,t}-v^s_{j,t}\rVert_2\big)\qquad w_{ij,t}=\frac{\tilde{w}_{ij,t}}{\sum_{j'\in\mathcal{N}_t(i)}\tilde{w}_{ij',t}}$$
$\kappa$ = decay rate — bigger $\kappa$ = "only very close neighbours count" $\mathcal{N}_t(i)$ = the neighbours of vertex $i$ Right equation just rescales weights to sum to 1
Laplacian coordinate (the arrow)
$$\Delta_t(V)_i=\sum_{j\in\mathcal{N}_t(i)}w_{ij,t}\,(v_i-v_j)$$
In plain English: $\Delta_i$ = vertex $i$ minus the weighted average of its neighbours = "how far, and in which direction, this point pokes out from its local group." Two shapes with the same $\Delta$ for every vertex have the same local structure, regardless of overall position, rotation, or size differences.

Interaction-mesh energy — the objective to minimize
$$E_{\text{IM}}(q)=\frac{1}{N_v}\sum_{i=1}^{N_v}\big\lVert\,\Delta_t\big(V^r_t(q)\big)_i-\Delta_t\big(V^s_t\big)_i\,\big\rVert_2^2$$
In plain English: for every vertex, compare the robot's local-shape arrow to the human's local-shape arrow. Square the differences, average over all $N_v$ vertices. Driving $E_{\text{IM}}$ to zero = the robot's hand-object interaction has the same local geometry as the human's — finger-to-object distances and directions preserved, even on a totally different hand.

Why this beats matching poses or fingertips directly: a fingertip-matching method says "put the robot tip exactly where the human tip was" — but the robot finger is a different length, so that forces penetration or floating. The Laplacian objective instead says "keep the tip the same relative distance/direction from the object surface," which adapts gracefully across hand shapes. That's why one parameter set works across different objects and even different robot hands (Figure 5).

6 Stage ④ — The full constrained solve

Combine everything, then add two hard rules: stay within the robot's joint limits, and do not penetrate the object.

Complete per-frame optimization
$$\big(q^{r,*}_t,\,s^*_t\big)=\arg\min_{q,\,s}\;\; \lambda_{\text{IM}}\,E_{\text{IM}}(q)\;+\;\lambda_{\text{bone}}\,E_{\text{bone}}(q)\;+\;E_{\text{reg}}(q;q^{r,*}_{t-1})\;+\;\frac{w_s}{2}\sum_{i\in\mathcal{Q}_t}s_i^2$$
In plain English: find the robot pose $q$ that simultaneously
• preserves interaction ($E_{\text{IM}}$),
• keeps human-like finger bends ($E_{\text{bone}}$),
• stays smooth & near a sensible base pose ($E_{\text{reg}}$),
• and uses as little "cheating" as possible (the slack term $\tfrac{w_s}{2}\sum s_i^2$). The $\lambda$'s are knobs that balance these. Crucially, the same $\lambda$'s work for every object and hand — no per-case tuning.

The no-penetration constraints (with slack)

$$\varphi_i(q)\ge -b\qquad\quad \varphi_i(q)+s_i\ge -\tau\qquad\quad 0\le s_i\le b-\tau,\quad i\in\mathcal{Q}_t$$
$\varphi_i(q)$ = signed distance for hand-object pair $i$ (negative = overlapping) $\tau$ = soft tolerance (tiny allowed touch) $b$ = hard bound (never cross this) $s_i$ = slack: how much pair $i$ is allowed to bend the soft rule $\mathcal{Q}_t$ = the hand-object pairs being checked this frame
In plain English: $\varphi_i$ is how far apart a finger and the object are (it goes negative if they overlap). The rules say: never penetrate past the hard limit $b$; try to respect the gentle limit $\tau$; and if a pair must slightly violate $\tau$ to make contact work, it "pays" via slack $s_i$, which the objective minimizes. This is exactly why max penetration drops to ~1 mm instead of 11–20 mm.

The regularizer, spelled out

$E_{\text{reg}}$ (Appendix A.1)
$$E_{\text{reg}}(q;q^{r,*}_{t-1})=\lambda_{\text{reg}}\lVert q-q^{r,*}_{t-1}\rVert_2^2 +\lambda_{base,pos}\lVert q^{base}_{pos}\rVert_2^2 +\lambda_{base,rot}\lVert q^{base}_{rot}\rVert_2^2$$
In plain English: three gentle pulls — (1) stay close to last frame (smooth motion), (2) don't drift the wrist position too far, (3) don't twist the wrist orientation too far. Keeps the solution physically reasonable and temporally stable.

A robot finger starts sunk inside the object ($\varphi<0$). The constraint pushes it out until it rests on the surface ($\varphi\!\approx\!0$) — contact preserved, no penetration.

7 What the robot does with the reference

The clean reference trajectory feeds a reinforcement-learning controller.

RL tracking controller (PPO). A policy is trained with PPO to track the retargeted trajectory, adding small residual actions to handle physics the reference didn't capture. Because the reference already respects contacts and feasibility, the policy explores far less and learns the skill much more reliably.
The payoff chain: better references → less wasted exploration → higher RL success rate → and because contacts are physically valid, the learned skill transfers zero-shot to the real Wuji Hand hardware (Figures 1 & 4: cube reorientation and pen spinning on the physical robot).
